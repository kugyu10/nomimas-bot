## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| フォーム入力 → server action | 未検証ユーザー入力がDB書込・scraper 起動に変換される地点 |
| server action → scraper Edge Fn | ユーザーJWTが外部関数呼び出しに使われる地点 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-10 | Tampering | createEvent/updateEvent 入力 | mitigate | server action 側で zod safeParse 再検証（クライアント検証を信用しない）。書込先 OA は RLS with check が最終検証 |
| T-03-11 | Server-Side Request Forgery | triggerScrape の URL | mitigate | zod regex で `https://twipla.jp/events/[0-9]+` の正規形強制 + scraper 側 canHandle 許可リスト（query/hash/port 拒否 — 実読確認済み）の二重防御 |
| T-03-12 | Repudiation | RLS 0行 UPDATE の成功偽装 | mitigate | data 層規約: update().select() 返却行数 0 → 「保存に失敗しました」（Task 1） |
| T-03-13 | DoS | scraper の連打起動 | accept | ボタン in-flight disabled + 30s timeout。scraper は読取系・登録URL完全一致で影響限定（RESEARCH 判断。恒久対策が要るなら Phase 4） |
</threat_model>
