## New / Changed UI Surfaces

### 1. テンプレート保存 Dialog

Insertion point: `admin/components/oa/question-list-editor.tsx` — add trigger button and Dialog to the component's action area (below the question list, alongside "質問を追加" button).

#### Trigger Button

```
[質問を追加]  [テンプレートとして保存]
```

- "テンプレートとして保存" button: `variant="outline"` `size="sm"`. Icon: `<BookmarkPlus className="h-4 w-4 mr-1" />`. Placed in same row as "質問を追加" (flex row, gap-2). **(auto)**
- Disabled when `questions.length === 0`. Tooltip text when disabled: "質問がありません" **(auto)**

#### Dialog Structure

```
┌─────────────────────────────────────────┐
│ テンプレートとして保存          [×close] │
├─────────────────────────────────────────┤
│ テンプレート名                           │
│ [________________________] ← Input      │
│ 例: 歓迎会の定型質問セット               │
│ ※ 現在の質問 {n} 件を保存します         │
├─────────────────────────────────────────┤
│ [保存しない]  [テンプレートとして保存]   │
└─────────────────────────────────────────┘
```

- Dialog title: "テンプレートとして保存" (20px/600)
- Input label: "テンプレート名" (12px/400, form label)
- Input placeholder: "例: 歓迎会の定型質問セット"
- Helper text below input: "現在の質問 {n} 件を保存します" (12px/400, muted color). `{n}` is interpolated at runtime.
- Footer: [保存しない (ghost variant)] [テンプレートとして保存 (default variant = bg-primary)]
- "テンプレートとして保存" button in footer: disabled while name input is empty or while save is in-flight. Shows spinner icon when in-flight. **(auto)**
- On success: dialog closes + show inline Alert (success): "テンプレートを保存しました"
- On error: dialog stays open + show error below footer: "テンプレートの保存に失敗しました。もう一度お試しください"

#### Interaction States

| State | Visual |
|-------|--------|
| Name input empty | Footer CTA disabled (opacity-50, cursor-not-allowed) |
| Saving in-flight | Footer CTA disabled + `<Loader2 className="h-4 w-4 animate-spin mr-1" />` |
| Save success | Dialog closes; parent shows success Alert |
| Save error | Dialog remains open; error text (14px/400 text-destructive) below dialog footer |

### 2. テンプレート適用 Select + 確認フロー

Insertion point: `admin/components/oa/question-list-editor.tsx` — add template-apply UI above the question list (between OA設定カードのセクションヘッダーと質問リスト).

#### テンプレート適用 UI Block

```
┌─────────────────────────────────────────────┐
│ テンプレートを適用                           │
│ [テンプレートを選択...  ▾] [テンプレートを適用] │
└─────────────────────────────────────────────┘
```

- Section label: "テンプレートを適用" (12px/400, muted, above the controls row)
- Select component (`<Select>`): placeholder "テンプレートを選択..." — lists all templates accessible to the current user (across all their OAs), formatted as "{テンプレート名}（{n}件の質問）". Width: 280px (`max-w-[280px]`). **(auto)**
- "テンプレートを適用" button: `variant="outline"` `size="sm"`. Disabled until a template is selected. Icon: none (text label alone is sufficiently specific). **(auto)**
- Empty templates list state: Select shows single disabled option "保存済みテンプレートがありません" (12px/400 muted).

#### 適用確認 AlertDialog (destructive-ish overwrite)

Triggered when user clicks "テンプレートを適用" with a template selected.

```
┌──────────────────────────────────────────────────┐
│ 現在の質問を上書きしますか？                       │
├──────────────────────────────────────────────────┤
│ 「{テンプレート名}」を適用すると、現在の質問 {n} 件  │
│ がすべて削除され、テンプレートの質問に置き換わります。 │
│ この操作は元に戻せません。                          │
├──────────────────────────────────────────────────┤
│ [適用しない]      [テンプレートを適用]             │
└──────────────────────────────────────────────────┘
```

- AlertDialog title: "現在の質問を上書きしますか？" (20px/600)
- AlertDialog description: "「{テンプレート名}」を適用すると、現在の質問 {n} 件がすべて削除され、テンプレートの質問に置き換わります。この操作は元に戻せません。" (14px/400). Both `{テンプレート名}` and `{n}` are interpolated at runtime.
- Cancel button: "適用しない" (`variant="outline"`)
- Confirm button: "テンプレートを適用" (`variant="default"` = bg-primary — NOT destructive variant; overwrite is reversible via Cancel, not a data-deletion action). **(auto)**
- On confirm: questions are replaced client-side (no server call at this point — questions are saved via the existing "設定を保存" flow). AlertDialog closes. Select resets to placeholder.
- On cancel: AlertDialog closes. Select retains current selection. No state change.

**Note:** "適用しない" / "テンプレートを適用" are the canonical labels. Abbreviated forms ("キャンセル", "適用") are forbidden.

## Interaction Contracts — Phase 4 Additions

### テンプレート保存 Dialog

1. Trigger button "テンプレートとして保存" opens `<Dialog>`.
2. Name input is focused automatically on dialog open (`autoFocus` on `<Input>`). **(auto)**
3. Submit via Enter key (form `onSubmit`) or footer CTA button — both trigger save action.
4. Escape key closes dialog without saving (shadcn Dialog default).
5. In-flight: CTA button disabled + spinner. Input disabled. **(auto)**
6. On success: Dialog closes. Parent area shows inline `<Alert variant="default">テンプレートを保存しました</Alert>` that auto-dismisses after 4 seconds. **(auto)**
7. On error: Dialog remains open. Error message (text-destructive 14px/400) appears below the description, above the footer.

### テンプレート適用 フロー

1. Select an item from the template dropdown.
2. Click "テンプレートを適用" — opens `<AlertDialog>`.
3. Cancel ("適用しない"): AlertDialog closes, select retains choice.
4. Confirm ("テンプレートを適用"): questions array replaced client-side. AlertDialog closes. Select resets to placeholder. No toast/alert needed — the question list visually updates immediately. **(auto)**
5. The template apply is a client-side state replacement only — it is persisted when the user subsequently clicks "設定を保存" (existing OA settings save flow). This is intentional; the user can review the applied questions before saving. **(auto)**

### loading.tsx Skeletons

- Displayed automatically by Next.js App Router when the async RSC for each route is resolving.
- No interaction required — purely visual placeholders.
- Skeletons match the approximate shape of the loaded content (column counts and row heights match the actual table layout) to minimize layout shift on content load. **(auto)**

### OA セレクタ 切替スピナー

- `useTransition` wraps the `router.refresh()` call in `oa-selector.tsx`.
- `isPending` drives the spinner display — no separate loading state needed.
- The spinner appears within the existing OA selector trigger (replacing chevron during transition). No additional DOM elements outside the selector. **(auto)**

## Accessibility Contract — Phase 4 Additions

Inherits all rules from 03-UI-SPEC.md. Phase 4 additions:

- テンプレート保存 Dialog: focus returns to trigger button on close (Radix Dialog default). `aria-label="テンプレートを保存するダイアログ"` on `<DialogContent>`. **(auto)**
- テンプレート適用 AlertDialog: follows Radix AlertDialog ARIA pattern. Confirm button ("テンプレートを適用") is focused on open per ARIA authoring practices. **(auto)**

- URL 行削除ボタン: `aria-label="URLを削除"` (explicit fix — see Section 5a above).
- loading.tsx skeleton containers: `aria-hidden="true"` on skeleton elements; `aria-busy="true"` on the outer wrapper. **(auto)**
